# 重聚巅峰脚本生成器

把用户的自然语言需求转换为可运行脚本三件套：

```text
BP.ini（或 banpick.ini）   禁用 / 首发 / 出战 / 被Ban方案
切换.ini                   全部换精灵规则
精灵出招\<精灵名>.ini      每个上阵精灵一份
```

适用：从零生成、修改现有脚本、补写单只精灵出招、只调整切换或 BP、校验脚本。

## 1. 通用规范

- 文件编码 **ANSI/GBK、无 BOM、CRLF 换行**（样本实测）。生成后必须保证。
- 行格式 `键=值`；值内多个项用**空格**分隔，不用逗号。
- 精灵出招默认行的键统一写 `技能`（137 份样本全部如此）；手册示例写 `默认`（样本中 2 个击杀文件也用 `默认`），两者兼容——统一用 `技能`。
- 区块顺序与空行不影响解析。

## 2. 标识符与动作词

处理自然语言时先把所有数字/代号归类，再写入 ini：

| 形态 | 含义 | 依据 | 处理 |
|---|---|---|---|
| 4 位数字 | 精灵 ID | 用户确认 | BP 名单、切换键/值、特判键 |
| 5 位数字 | 技能 ID | 用户确认 | 精灵出招动作序列 |
| `5` | 动作码 | 样本广泛出现；手册仅作示例动作、未定义 | 原样保留，不新造 |
| `0` | 动作码 | 样本仅 `星礼.ini` 使用；手册未定义 | 原样保留，不新造 |
| `1000001` | 特殊动作码 | 样本 116 个文件使用；手册未定义 | 原样保留，不新造 |
| `hp` / `pp` | 吃药 | 手册（仅小写；hp=150HP药，pp=10PP药） | 原样写入 |
| `切走` | 普通切换 | 手册 | 原样写入 |
| `特判切走` | 特判切换（不一定走全局切换） | 手册 | 原样写入 |

ID 查找（禁止编造，按优先级）：

1. 查工作区中的精灵图鉴/信息文件（含 精灵名↔ID、技能名↔技能ID，例如 `build-seerapi-encyclopedia` 生成的文本图鉴）。
2. 从样本 `精灵出招\<同名精灵>.ini` 复制技能 ID。
3. 仍缺失 → 询问用户。

## 3. BP.ini

```ini
[BP]
禁用=精灵ID ...          ← 我方禁用（自由战不生效，可空）
首发=精灵ID ...          ← 默认首发，有序
出战=精灵ID ...          ← 默认出战，有序，尽量写满 12 只

[ID1/ID2/ID3]            ← 可选“被Ban方案”，1~3 个条件
首发=精灵ID ...
出战=精灵ID ...
```

规则：

- `首发` 应存在于 `出战`；被禁用时自动取下一个。
- 条件节从上到下判断；更具体（3 条件）写前面，其次 2 条件、1 条件。
- 3V3 只用 1~2 个条件（写 3 个会走默认）。
- 名称模糊匹配：手册确认**条件、首发、出战**支持精灵名称；但生成时统一用 4 位 ID 更稳妥。
- 条件节内同时写 `首发` 与 `出战`。

## 4. 切换.ini

所有切换区块的值都是**空格分隔的精灵 ID 候选队列**，按顺序取第一个可用。

| 区块 | 名称 | 键（判断条件） |
|---|---|---|
| `[切走]` | 切换列表（判断我方精灵） | `默认` / 我方当前精灵 ID |
| `[击杀切走]` | 击杀切换（需手动写生效） | `我方ID>对方ID` 等 4 种组合 |
| `[T我方精灵ID]` | 中途切换（中切，占回合，对方精灵=更换精灵） | `默认` / 对方精灵 ID |
| `[S我方精灵ID]` | 针对死切（不占回合，对方精灵=更换精灵） | `默认` / 对方精灵 ID |
| `[死亡切换]` | 死亡切换（不占出招回合，对方精灵=更换精灵） | `默认` / 对方精灵 ID |
| `[我方精灵ID]` | 旧版普通精灵特判切 | `默认` / 对方精灵 ID |

示例：

```ini
[切走]
默认=5000 3550 3788 ...
3613=4677 4816 4717 ...

[击杀切走]
默认>默认=5000 3788 ...        ← 必填保底，否则可能卡出招
默认>5000=4186 4800 ...
4717>默认=5000 3788 ...
4717>4717=4620 4509 ...

[死亡切换]
默认=5000 4321 2987 ...
5000=4186 4749 4318 ...        ← 对方 5000 在场时

[S3613]
默认=4661 4387 ...             ← 我方 3613 死亡
4163=4620 4797 ...             ← 对方 4163 在场时

[T3613]
默认=4468 4816 ...
4677=4553 4693 ...
```

查找顺序（重要）：

- 活切（普通特判）：`[我方ID]` → `[切走]` → 找不到则执行后续动作。
- 中切：`[T我方ID]` → `[我方ID] 默认` → `[切走]` → 找不到就不切（弱切）。
- 死切：存在任一 `[S...]` 则走 S 体系（此时 `[我方ID]` 在死切中失效）→ `[S我方ID]` → `[死亡切换]` → 找不到强制按顺序切；没有任何 `[S...]` 时，死切走旧 `[我方ID]`。
- `[击杀切走]` 优先级：双方指定 > 我方指定 > 对方指定 > 默认>默认。

## 5. 精灵出招（精灵出招\<精灵名>.ini）

文件名用精灵真名（可含 `·`，建议完整连续名称）。

| 区块 | 触发 | 要点 |
|---|---|---|
| `[循环]` | 常规每回合 | 序列不去重，按顺序反复执行；对方换人后重置为第一招并重新判定 |
| `[登场]` | 同起/普通登场 | 一次性，执行完进循环 |
| `[中切登场]` | 我方中切登场（含被天尊驱逐） | 与 `[登场]` 独立 |
| `[死切登场]` | 我方死亡换人登场 | 没有则兼容回退 `[登场]` |
| `[击杀]` | 击杀对方后下一回合 | 每行只能写一个动作 |
| `[中切特判登场]` | 中切且使用“特判切走”（2.4.2+） | 写了就必须覆盖完整，否则不回退 `[中切登场]` |

行结构：

```ini
[循环]
技能=动作序列           ← 默认行
对方精灵ID=动作序列      ← 特判行
```

硬性规则：

- `[击杀]` 每行只能一个动作；写 `切走`/`特判切走` 触发击杀切走（两者等效）。
- 两个切换动作（`切走`/`特判切走`）不能相邻；`[循环]` 里首尾也不能都是切换动作（循环首尾相接会卡出招）。
- `[循环]` 默认行不能整行只写一个 `切走`/`特判切走`（会空过）；`[登场]` 可以只写一个 `切走`。
- 切走失败后执行该行后续动作，不会卡住。
- 击杀后 n+1 回合：击杀特判 → 击杀默认 → 循环默认1；n+2 回合：新精灵循环特判 → 循环默认2。

## 6. 校验与交付

1. 运行 `python scripts/validate.py <输出目录>`；修复所有 ERROR，逐条判断 WARNING。
2. 输出目录必须含 `BP.ini`（或 banpick.ini）、`切换.ini`、`精灵出招\` 文件夹。
3. 确保 ANSI/GBK、无 BOM、CRLF。
4. 覆盖旧脚本前先备份。
5. 交付说明列出：生成文件、采用的假设、未确认项、建议实测场景；最终以游戏内加载为准。

## 7. 内置资源

- `assets/templates/`：三件套骨架，复制后改写。
- `assets/standard-ids.txt`：常用对方精灵 ID 池（来自样本模板），用于批量生成特判行。
- `scripts/validate.py`：结构校验器。

## 8. 禁止事项

- 不编造精灵 ID / 技能 ID。
- 不发明 `5`/`0`/`1000001` 的新用法。
- 不在 `[击杀]` 写多招。
- 不生成相邻或（循环内）首尾相邻的切换动作。
- 不把 `[中切特判登场]` 写成只覆盖部分对手（除非用户明确接受不回退）。

## 9. 补充规则（可选，按需使用）

- 脚本说明：可加 `[脚本说明]` 区块，`说明=提示内容`，在脚本界面显示提示。
- 一键换精灵：额外文件 `精灵预设.ini`，`[背包]` 下 `1=精灵ID 精灵ID ...`、`2=...`，支持 ID 或名称；可选“100 级 / 任意等级”两种模式。
- 吃药：`hp`=150HP药、`pp`=10PP药（仅小写）；勾选“吃高级HP药”后优先级为 250永寒体力 → 200 → 150，且对应药剂数量需 >50；“被控吃药”建议勾选“占用出招回合”，否则连续被控可能无限吃药不切精灵。
- 排查“卡出招”顺序：先判状态（同起/中切/死切/击杀）→ 有无对应特判 → S/T 是否覆盖旧体系 → 有无默认保底 → 是否切走失败/锁切 → 是否相邻切换动作 → 是否击杀后信息尚未更新。
