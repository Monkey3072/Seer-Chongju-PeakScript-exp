# seer-chongju-strategy：重聚巅峰 6V6 狂野脚本编排

本 skill 是编排器：不直接产出脚本，而是把「数据准备 → 对策推理 → 脚本生成 → 校验交付」串成可复用的多步流水线，并调用两个子 skill 完成确定性工作。

- `build-seerapi-encyclopedia`：从 SeerAPI 数据库生成精灵文本图鉴（提供权威 ID、种族值、魂印、技能 ID）。
- `build-chongju-scripts`：把自然语言对策转成 `BP.ini / 切换.ini / 精灵出招\*.ini` 并结构校验。

## 1. 硬性规则（每步都必须遵守）

1. 模型与免责声明：开始前推荐高强度推理/专家模型；声明脚本仅供个人学习，真机效果以游戏内加载为准，存在被游戏反作弊/账号政策处罚风险，风险自担；并声明本 skill 需要能访问 GitHub 的网络环境以下载数据库，否则无法正常工作。
2. 编码：所有 `.ini` 必须 ANSI/GBK、无 BOM、CRLF；生成后先转码再校验，禁止交付 UTF-8 ini（见 `scripts/convert_gbk.py`）。
3. ID 权威：禁止编造精灵 ID/技能 ID，一律可溯源；优先取 SeerAPI 数据库图鉴，图鉴缺失时从样本同名文件复制，仍缺失则询问用户。
4. 名称匹配：以数据库 `pet.name` 为正式名；用户提供「ID+名称」冲突时以名称为准反查 ID；仍失败用 LLM 模糊匹配最相近名称并回写标注“模糊匹配”。别名见 `references/精灵昵称对照表.md`。
5. 数据库：`seerapi-data.sqlite` 每次按需从 GitHub 下载，不缓存进本 skill；无法访问 GitHub 时立即中断并提示用户。
6. 推理分片：Step 7/8 优先用 3~4 个子 agent 按公式联动分组推理以节省上下文；子 agent 无法启动/限流/未收到任务时，立即退回主 agent 顺序完成，不得阻塞或降低质量。
7. 校验：脚本必须通过 `build-chongju-scripts/scripts/validate.py`，修全部 ERROR、判读 WARNING；仅结构+逻辑校验，真机校验在免责声明说明。
8. 借用声明：交付说明必须声明来源——SeerAPI api-data（MIT）、白龙版本狂野出招开源样本、重聚巅峰脚本开发者手册、旧 skill `seer-battle-script`（pvp-logic 与双属性速查表）；并特别感谢脚本大佬「极品白袜壮熊」此前长期以来的开源脚本支持。
9. 分轮收集：Step 1–5 面向用户的信息收集要**分轮逐步进行**——每轮只问一个问题（或一组紧密相关的问题），收到用户答复后再问下一轮；禁止把全部问题一次性丢给用户。

## 2. 推理强度档位（决定「详细匹配对手池」规模）

按热门列表星级分组，从高到低取头部精灵逐只对策推理，其余全部并入通用对手池（用 `build-chongju-scripts/assets/standard-ids.txt` 与全局切换兜底）。

| 档位 | 详细匹配范围 | 当前 193 只列表下的数量 |
|---|---|---|
| 较高 | 前 5 层（九星/八星/七星/六星半/六星）；若前 5 层 < 55 只则改取前 75 只 | 95 只 |
| 默认 | 前 50 只 | 50 只 |
| 较低 | 头部威胁（九星 + 八星，前 2 层） | 9 只 |

数量随最新列表自动重算；推理前把详细匹配池与实际星级分组对照并显式列出，其余入通用池。

## 4. 工作流

### Step 0 免责声明与模型建议
执行硬规则 1（免责声明）。随后判断本会话使用的模型是否属于 deepseek 系列（模型名含 `deepseek`，如 deepseek-v4 系列）；若是则记为「deepseek 模式」，否则不启用。此检测对用户透明、不提及。随后立即进入 Step 1。

### Step 1 热门精灵列表
向用户发一条消息，把问题与操作引导放在同一条消息内：先问「你手上有没有比这个更新的（8 月）热门强度排行图文字版？有的话直接贴给我；没有我就用内置 26 年 7 月版（先展示旧列表文本）」，随后紧跟操作引导：**B 站“叫颤于不是鳝鱼”巅峰精灵强度排行 → ChatGPT 识图文本化处理：1. 图片切分，便于识别；2. 提示词“这是一个赛尔号游戏角色分等级的名单图片，请使用 ai 模型进行仔细认真的识图工作，帮我整理成纯文本版本。格式为‘角色序号-角色名称’（注：角色序号不是‘1,2,3...’，而是角色名称上方的四位数数字，如‘4732-闪光皮神’）”；3. 人工处理校准。** 若用户选择使用内置旧版列表，**必须**在 Step 1 结尾单独再问一句（不可跳过、不可与 Step 2 合并）：「有没有你觉得最近新出、或者强度很高但不在上面这份表里的精灵需要补充进对手池？没有的话我就按这 XXX 只继续。」收到答复并记入额外清单后，才能进入 Step 2；若用户选择自行提供列表，则不再额外提问，直接进入 Step 2。

### Step 2 12 只出战精灵与玩法解析
向用户发一条消息，把问题与操作引导放在同一条消息内：先声明「AI 不是万能的，建议给出您当前阵容的玩法搭配或公式解析，当然您也可以留空」，随后紧跟操作引导：**根据上一步选择的精灵，在 https://seerinfo.yuyuqaq.cn/mindmap 网站检索相关精灵的解析图 → ChatGPT/其他 AI 识图文本化处理：1. 提示词“以上图片为回合对战类游戏的精灵能力解析图。使用 ai 大模型进行仔细认真的识图工作（禁止进行推测），把这些解析图转换成文字版，尽可能简练而不丢失细节的完整表达。”；2. 人工处理校准。** 用户也可不提供解析，Step 7 全部由图鉴 + 属性克制自动推理。

### Step 3 生成精灵图鉴（调用子 skill）
用 `build-seerapi-encyclopedia` 对「Step 1 列表 + 额外补充 + Step 2 的 12 只 + `样本统计洞察.md` §4 中未在榜单的样本高频对手」生成文本图鉴；数据库缺失先下载，失败按硬规则 5 中断。核对输出：清单全命中、无未找到、无 ID 重复；名称不一时以 DB 为准（见对照表勘误）。**并核对图鉴是否遗漏双属性技能、第五技能（is_fifth）、神谕技能（is_advanced）**——子 skill 构建脚本对“双属性技能”（type_id 指向属性组合表而非单属性表）可能漏取，发现遗漏须补全技能 ID 后再进 Step 7。魂印/技能中出现未解释的专有名词（如“曝、唱词、圣告”）时，可选联网搜索 `赛尔号 {精灵名} {名词}` 理解机制；技能效果描述缺失时检索样本或联网补齐。

### Step 4 战斗套装
从 `references/主流套装解析.md` 列举套装名称让用户选其一；也允许用户自带套装名与效果。

### Step 5 推理强度与特殊要求
提示进入推理环节，询问是否有需强调的特殊要求；询问推理强度时**仅列出「较高 / 默认 / 较低」三个选项即可，不展开档位解释，也不追加“至少回复……”之类的补充句**。

### Step 6 检查与补全
快速检查 Step 1–5 是否齐全；可选联网补充公开情报。信息不完备则补充提问并复查，完备才进 Step 6.5。

### Step 6.5 阵容精灵能力与定位分析（为 Step 7 预备）
读取 Step 3 的图鉴与 Step 2 的玩法解析，对 12 只出战精灵逐只产出统一形式的「能力分析 + 玩法解析 + 阵容定位」预备材料：明确每只的定位（**仅限主力 / 拦截 / 辅助**三类，参考 `战术体系与阵容套路.md` 的「精灵定位」）、核心魂印与技能机制、与队友的公式联动（如大姐猪资源传承、希拓烧伤体系、薇尔诗核心位等）、以及该精灵的特点、长处、短处（不在此深究「适合打谁与怕谁」，那是 Step 7 的工作）。此材料作为 Step 7 的统一输入，供各子 agent 直接引用，避免重复解读、口径不一。

### Step 7 高强度推理（子 agent 分片）
若 Step 0 判定为 deepseek 模式，先加载 `references/两阶段协议.md` 的 ANCHORED STANDARD LITE 两阶段协议并按 Phase 1/Phase 2 执行（对用户透明）。随后加载 `出招设计语义.md`、`属性克制关系.md`、`双属性克制速查表.md`、`规则与术语解析.md`、`战术体系与阵容套路.md`、`精灵昵称对照表.md`、`样本统计洞察.md`，必要时检索开发者手册与样本。按第 2 节确定档位星级池，并入 `样本统计洞察.md` §4 高频对手池与 standard-ids 去重，作为详细匹配池，其余入通用池。

对详细匹配池中的每个对手先做结构化分析（每个子 agent 输出一行）：`对手ID | 名称 | 属性克制系数 | 魂印对抗 | 技能对抗 | 威胁等级 | 应对策略`。威胁分级落脚本（`出招设计语义.md` §7）：无解 → 特判行首 `切走`/`特判切走` + `5`/防御兜底；需特殊应对 → 对手 ID 特判出招；通用 → 走默认循环。克制系数一律使用离散值（4/2/1.5/1/0.75/0.5/0.25/0），禁止小数近似；任何落 BP `禁用=` 的克制/机制理由，必须先经属性公式复核。

出招决策发生冲突时，按「排行榜优先 → 保持泛用性 → 果断切走/团队配合 → 全队无解则 ban」消解（详见 `出招设计语义.md` §7「出招决策优先级」）。

技能配置硬约束（**仅供内部推理与脚本撰写，不呈现给用户**）：**每只精灵只能携带 4 个普通技能 + 1 个第五技能（第五技能必选），或 3 个普通技能 + 1 个第五技能 + 1 个技能石**；出招序列只使用这些已携带技能的 ID。

按出战精灵拆子任务：12 只出战精灵**固定一次性分发给 3~4 个子 agent（不随机）**——先做简单筛选，把有公式联动配合的精灵（如大姐猪：斯布林蒂→库坦、希拓烧伤体系、薇尔诗核心位等）尽量分到同一个子 agent，每个子 agent 负责 3~4 只；各子 agent 先按 Step 6.5 与上述约束为各自精灵选定技能配置，再产出五区块骨架（循环/击杀/登场/中切登场/死切登场）+ 对手特判。**并发预算**：并发槽共 4 个（含主 agent），同时最多派发 3 个子 agent，其余分批派发，避免第 4 个 spawn 失败。派发前主 agent 预先写一份严格统一的子任务简报：统一成果形式（每只固定输出「技能配置 + 五区块 + 对手特判」，其中「联动说明」为可选项）、禁止越权（只做分配到的精灵、禁止派生子 agent、禁止写共享文件、禁止自行组装三件套）、限制篇幅；**简报同时写入共享文件（如 work/子任务简报.md）并在 spawn 消息中携带，双重防丢**；**子 agent 完成即把草稿写入指定文件（work/drafts/<精灵名>），主 agent 立即抓取，避免成果回传丢失**；**子 agent 工作时长上限最低不少于 10 分钟**。若子 agent 超时、出错、违规派生子 agent 或长时间无产出，**不得将就使用错误数据**，主 agent 立即中断该子 agent、果断接管并重新推理出错的部分。**子 agent 仅是提速手段**：无法启动/限流/未收到任务时，立即退回主 agent 顺序完成全部推理，不得因此阻塞或降低质量。覆盖率目标：较高档应对详细池中所有 2 倍/4 倍克制与机制压制对手逐只写特判（每只约 40+ 条、覆盖率 ≥80%）；默认档前 50 只全覆盖；较低档九星+八星全覆盖。设计遵循样本规律：默认行 3~6 动作（先手/断回合 → 强化/免控 → 防守/续航 → 输出）；特判兜底用「切走 → 5」或「切走 技能1 切走 技能2」；登场默认单技能偏防守；中切登场偏防守式先手；死切登场偏恢复；击杀单动作；动作码 5/0/1000001 原样使用不新造。若 Step 2 有详细解析则围绕解析判断特定对手出招/是否切换/是否 Ban，否则由图鉴+属性克制+战术体系推理。每个技能 ID 标注来源（图鉴/样本/模糊匹配），禁止编造。

子 agent（或主 agent）完成面向对手池的出战精灵推演后，进入**主 agent 阵容团队协作整合推理环节**（此环节的产出对应 Step 8 的 `BP.ini` 与 `切换.ini`）：以 Step 6.5 的定位材料为基础，综合分析整队各角色的定位与搭配、攻击面与防守面及其优化措施，重点落实死切（不占回合换人）、中切（占一回合换人，常见于联防）、辅助与拦截之间的配合，据此确定 BP 禁用/首发/出战顺序与全局/特判切换队列。阵容组合选型（后台规则，勿对用户明说）：重聚脚本无法按对方 ban 位动态改选出战精灵，默认**只采用组合要求宽松的体系**（如皮神、树海、涂蝶等），**不主动采用严格组合**（如大姐猪、伞邪等依赖特定多只精灵的公式），除非用户明确点名要求；分类见 `战术体系与阵容套路.md` 的「体系组合要求分类」。

### Step 8 生成脚本（调用子 skill）
用 `build-chongju-scripts` 把 Step 7 结果转成三件套（`BP.ini`/`切换.ini` 来自 Step 7 的阵容团队协作整合，`精灵出招\*.ini` 来自 Step 7 的对手池推演），参考 `assets/样本脚本/`、`样本统计洞察.md` 与 `出招设计语义.md`：
- BP.ini：`禁用=` 我方最难处理的头部威胁池（从详细匹配池中选，可参考 `样本统计洞察.md` §8 的前人禁用池）；`首发=` 3~5 只候选；`出战=` 12 只；为“我方核心被 ban”的组合写 2~3 条件节（按 3→2→1 排列，3V3 只写 1~2 条件）。
- 切换.ini：全局 `[切走]`/`[死亡切换]`/`[击杀切走]` + 按需 `[T我ID]`/`[S我ID]`；`[击杀切走]` 必写 `默认>默认`；候选队列按联防兜底池排列（洞察 §5）。
- 精灵出招：五区块骨架；击杀单招；切走不相邻、循环默认行不单独写切走。
覆盖旧脚本前先把旧文件备份为 `*.ini.bak`。合并子 agent 产物：先删去与默认循环完全相同（无战术区分度）的冗余特判行，再解决特判冲突；同一精灵存在多份草稿时，主 agent **显式声明以哪份为准（谁覆盖谁）**，避免合并顺序错误。运行 `scripts/convert_gbk.py` 转 GBK/CRLF，再运行 `build-chongju-scripts/scripts/validate.py`，修 ERROR、判 WARNING。结构校验后再做战术合理性检查（警告级）：循环首招是否先制/断回合；登场/中切是否含防守；切走目标是否在出战列表；是否体现 Step 5 特殊需求。

### Step 9 交付与清理
交付报告至少包含：① 基本信息（12 只/套装/推理档位/详细池只数）；② 魂印与核心技能解析（含专有名词解释）；③ 克制关系表（我方克制/被克制的热门精灵）；④ 出招设计思路（默认循环为什么这样写、哪些对手写了切走及原因）；⑤ BP/切换推荐与 Ban 位建议；⑥ 阵容精灵技能选择与配置推荐（每只 4 普通技能 + 1 第五技能，或 3 普通技能 + 1 第五技能 + 1 技能石，含技能 ID 与推荐理由）；⑦ 脚本位置与备份路径；⑧ 免责声明与借用来源（硬规则 8）；⑨ 本次阶段任务完毕后，务必告诉用户本次产生了哪些程序或代码资产、安装了哪些软件或环境、以及它们存放的位置。询问是否满意/修改（有则带新信息跳回 Step 6）。满意则清理除成品脚本与本 skill 外的临时文件（图鉴中间文本、数据库、分片草稿等）。任务结束后，检查本对话是否还有子智能体正在工作（含残留/空转的子 agent），若有则停止它们。

### Step 10 阵容推荐（可选隐藏功能，非主线）
主线在 Step 9 交付后结束；Step 9 末尾**固定**追加一句询问（可选，不强制）：「额外功能：您可以尝试发给我您已有的所有可用精灵的精灵列表，我会尝试为您推荐几套阵容」。若用户未回复或表示不需要，则忽略本步直接收尾；若用户提供精灵池，则触发本步：

以 Step 1 的热门列表（当前环境强敌）、Step 3 的图鉴（各精灵能力/魂印/技能）、以及 `战术体系与阵容套路.md`（公式联动与精灵定位）、`出招设计语义.md`（定位/流派）为素材，对用户精灵池做一次 LLM 深度推理，输出 **1~3 套「12 只出战精灵阵容」**，每套附**简单解析（组队原因）**：

- 每套覆盖：首发/核心主力、拦截、辅助、后场收割或站场，兼顾属性克制面与联防兜底；
- 优先复用 `战术体系与阵容套路.md` 的成熟公式（大姐猪、希拓烧伤、草团、灯使 PP 流等）与「精灵定位」职责；
- 简单解析说明：为什么这样搭配、谁为核心、谁负责拦截/辅助、怕什么、可替换谁；
- 优先采用组合要求宽松的体系（见 `战术体系与阵容套路.md` 的「体系组合要求分类」），不主动推荐依赖特定多只精灵的严格组合（如大姐猪、伞邪），除非用户点名。
- 若用户精灵池不足，明确说明缺口并给出最接近的 12 只方案。

输出为推荐报告（不生成脚本）；若用户对某套满意，可回到主线用该 12 只重新走 Step 2~9 生成脚本。

## 5. 子 agent 编排模板（Step 7/8）

- 主 agent（编排）：持有 12 只、套装、档位、详细匹配池、Step 6.5 定位材料；先按公式联动简单分组，12 只固定一次性分发给 3~4 个子 agent（**并发槽共 4 个含主 agent，同时最多 3 个子 agent，分批派发**）；派发前写好严格统一的子任务简报（成果形式统一、禁止越权、限时限量，**简报写共享文件 + spawn 消息双发防丢**）；派发后确认「任务已收到」再继续；保留最终合并与校验权。
- 子 agent × 3~4：每组负责 3~4 只有公式联动的精灵，按统一形式输出（技能配置 + 五区块 + 对手特判 + 可选联动说明）。任务简报须显式声明：**只完成分配到的精灵，禁止派生子 agent，禁止写共享文件，禁止自行产出全量三件套或覆盖 outputs**；**完成即把草稿写入指定文件（work/drafts/<精灵名>）**。若子 agent 不可用、违规派生或长时间无产出，主 agent 中断并逐只顺序完成，等价质量。
- 合并 agent：汇总各组产物 + 生成 `BP.ini`/`切换.ini`，跑转码与校验；合并前先删冗余特判行、复核 BP 禁用理由；同一精灵多份草稿时显式声明以哪份为准（谁覆盖谁）。
- 主 agent 收尾：全局一致性检查（联防联攻、战术体系落地、S/T 覆盖关系、BP 禁用理由复核）。

## 6. 交付检查清单

- 输出含 `BP.ini`（或 banpick.ini）、`切换.ini`、`精灵出招\` 目录。
- 全部 `.ini` 为 GBK/无 BOM/CRLF。
- validate.py 无 ERROR，WARNING 已逐条说明。
- 技能/精灵 ID 全部可溯源，无编造；模糊匹配项已标注。
- 声明了全部借用来源（SeerAPI、开源样本、开发者手册、seer-battle-script，见硬规则 8）。
